# BUG-001: Invalid temperature measurement does not trigger FAULT

**Status:** Fixed  
**Severity:** High (project assessment)  
**Component:** MotorController  
**Detected by:** GoogleTest — `InvalidTemperatureNaN`

## Description

The motor controller does not detect an invalid temperature measurement represented by `NaN`. As a result, the controller remains in `STOPPED` instead of transitioning to the expected `FAULT` state.

## Preconditions

- Motor controller initialized.
- Controller state: `STOPPED`.

## Steps to reproduce

1. Create a `MotorController` instance.
2. Call `initialize()`.
3. Call `updateTemperature(std::numeric_limits<double>::quiet_NaN())`.
4. Check the controller state using `getState()`.

## Expected result

The controller transitions to `MotorState::FAULT`.

## Actual result (before fix)

The controller remains in `MotorState::STOPPED`.

## Root cause

The original implementation only checked whether the temperature was greater than or equal to the configured threshold. Comparisons with `NaN` evaluate to false, so the invalid measurement was not detected.

## Resolution

Added input validation using `std::isfinite()` before checking the temperature threshold.

## Verification

- Before fix: `InvalidTemperatureNaN` — FAIL.
- After fix: `InvalidTemperatureNaN` — PASS.
- Regression suite: 20/20 tests passed.
