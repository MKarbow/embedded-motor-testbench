# BUG-002: Invalid Voltage Measurement Accepted by Motor Controller

**Status:** Fixed  
**Severity:** High (project assessment)  
**Component:** MotorController  
**Test Case:** MotorControllerTest.InvalidVoltageNaN  
**Environment:** Windows, C++17, GoogleTest, CMake, Ninja

## 1. Description

The motor controller incorrectly accepts an invalid voltage value (`NaN`) and transitions to the `RUNNING` state.

This violates the project's requirement that motor operation is permitted only when the supplied voltage is within the valid range of 15.0 V to 21.0 V.

## 2. Preconditions

- Motor controller is initialized.
- Controller state is `STOPPED`.

## 3. Steps to Reproduce

1. Create a `MotorController` instance.
2. Initialize the controller using `initialize()`.
3. Call `start()` with `std::numeric_limits<double>::quiet_NaN()`.
4. Check the return value of `start()`.
5. Verify the controller state using `getState()`.

## 4. Expected Result

- The `start()` method returns `false`.
- The controller remains in the `STOPPED` state.

## 5. Actual Result (Before Fix)

- The `start()` method returns `true`.
- The controller incorrectly transitions to `RUNNING`.

## 6. Root Cause

The original voltage validation relied on the following condition:

`voltage < 15.0 || voltage > 21.0`

Both comparisons return `false` when the voltage is `NaN`. Consequently, the invalid input bypasses validation.

## 7. Resolution

Added `std::isfinite()` validation to reject non-finite voltage values, including `NaN`, positive infinity and negative infinity.
